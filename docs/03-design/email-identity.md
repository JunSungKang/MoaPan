# 이메일 인증·복구 설계서

> 문서번호: MP-DOC-037 · 상태: 구현·검증 중 · 작성: 개발 담당 · 검토: 독립 리뷰 담당

## 1. 승인 요구

신규 가입은 아이디·비밀번호·인증된 수신 이메일과 이용 안내 확인이 필요하다. 아이디 1~128자, 비밀번호 6~128 Unicode code point를 유지한다. 이메일은 가입 인증, 비밀번호 재설정, 결제·구독 관련 안내에만 사용하고 마케팅·광고·다른 목적 사용을 금지한다. 결제 및 구독 안내는 향후 실제 결제 기능에 연결할 범위이며 현재 청구 기능은 없다. 관심사·검색 이력은 이메일과 연결하지 않는다.

## 2. 도메인 경계

identity/domain은 입력 정책과 닫힌 EmailPurpose 열거형, application은 인증 증명·계정 변경·암호화 outbox와 MailTransport 포트, infrastructure는 AES-GCM/HMAC·SMTP TLS·스케줄링, api는 요청 DTO를 소유한다. 외부 SMTP가 실행돼도 서비스 도메인은 SMTP 제품에 의존하지 않는다. 수신자·본문을 임의 입력받는 관리자 발송 API나 마케팅 동의/배치 발송은 없다. 고정 템플릿은 가입/메일 변경 인증, 비밀번호 복구 인증, 비밀번호/메일 변경 보안 알림만 허용한다.

## 3. 저장·보안·상태 전이

V25는 기존 users에 nullable 이메일 암호문·HMAC 조회키·인증/안내 확인 시각을 추가한다. 기존 계정은 이 값이 모두 null인 채 보존한다. 신규 가입과 기존 계정 등록은 인증 후 원자적으로 다섯 값을 채운다. 이메일 전체를 소문자로 정규화하고 별칭/점 제거는 하지 않는다. ASCII 주소만 지원하며 중복 인증 주소는 한 계정만 사용한다. 소문자 정규화의 한계로 대소문자 구분 메일함은 지원하지 않는다.

32-byte 전용 이메일 데이터 키는 MOAPAN_SECRET과 분리하며 운영 파일/Secret에서 읽는다. AES-GCM은 레코드 ID와 용도를 AAD에 결합한다. HMAC은 주소 조회·요청 제한·코드 검증마다 용도를 분리한다. 원문 이메일은 본인 전용 조회/처리 메모리/SMTP에서만 사용하며 세션 principal·공개 계정 DTO·관리자 회원 목록에 넣지 않는다.

인증번호는 CSPRNG 6자리, 5분, 1회 사용, 오입력 5회 시 폐기, 동일 주소 재발송 60초 제한이다. 주소당15분5회, 세션당15분10회, 전체시간당300회 발송 제한 및 검증 요청 제한을 적용한다. 발급은 세션과 사용자명에, 복구/변경은 계정과 auth_version에도 결합한다. 다른 세션의 증명은 사용하지 못하고 소유자의 실패 횟수도 소모시키지 못한다. PostgreSQL 잠금과 트랜잭션으로 동시 1회 사용을 보장한다. 초기 저용량 서비스의 인증 발급/소비는 동일 advisory lock과 계정→도전 순서로 직렬화하며 발송은 트랜잭션 밖이다.

복구 요청은 계정 존재 여부와 무관하게 동일한 202 구조와 일반 인증 메일을 발송한다. 일치하는 인증 계정이 없는 코드는 계정 변경에 사용할 수 없다. 이메일 받은 사람에게 계정 존재 여부를 명시하지 않으며 메일 폭탄 위험은 제한 카운터로 줄이지만 완전 차단은 보장하지 않는다. 성공 시 비밀번호 교체·auth_version 증가·모든 세션/기존 인증 도전 폐기가 원자적으로 이뤄진다. 자동 로그인하지 않는다.

## 4. 발송·운영

암호화 outbox는 worker만 소비한다. SKIP LOCKED 선점, 60초 lease, 최대3회/15초 재시도, 발송 후 내용 폐기, 만료/하루 이상 메타데이터 정리를 적용한다. SMTP 수락은 실제 받은편지함 도착의 증거가 아니며 lease 재시도는 중복 발송 가능성이 있는 at-least-once다. 인증 메일과 알림은 서비스 메일이며 뉴스레터 이메일 발송과 구분한다.

SMTP는 STARTTLS 필수 또는 SMTPS, 인증서/호스트 검증, 연결/읽기/쓰기3초 제한을 적용한다. 운영자가 지정한 CA는 SMTP 전용 SSLContext에만 적용하며 JDK truststore/TLS 검증을 변경하지 않는다. 형제 mail-box 원본에는 TLS/SASL이 없어 원래 구성을 그대로 공개 릴레이로 실행하지 않는다. 실제 전달·도메인 DNS 설정은 별도 운영 검증이 필요하다.

## 5. 안내·이행

가입 화면에 정확한 용도와 필수 확인, 계정 화면에 등록/변경, 로그인 화면에 복구 링크를 제공한다. 이메일 미등록 기존 회원은 계속 로그인 가능하지만 이메일 복구를 사용할 수 없으므로 등록을 안내한다. 운영자 연락처·결제·법률 검토 완료는 임의 생성하거나 주장하지 않는다. 별도 키의 백업/복원은 암호화 DB 백업과 함께 접근통제하며 키가 없으면 이메일 복구가 불가능하다. 실제 결과는 MP-DOC-038을 따른다.

## 6. 메일서버 이식과 실제 검토

MailBox 소스2개를 Apache-2.0 고지와 SHA256으로 동결했으며 소유자 원본은 수정하지 않았다. Debian12/13 기반에서 미해결 OS 취약점이 남아 배포하지 않고, 지원되는 Alpine3.24.3과 Postfix3.11.7로 이식했다. 원본 계정 목록/웹메일/IMAP은 가져오지 않는다. Linux 이관 시 형제 저장소 없이 포함 소스로 동일한 build context를 생성한다. Alpine 패키지의 vmail과 LMDB maps를 사용하며 private TLS 키는 chroot 내부 tmpfs에만 복사한다. 외부 SMTP도 verify/hostname/공식CA로 강제한다. 도메인별 호환성보다 TLS 실패 시 대기/만료를 우선하며 평문 fallback을 허용하지 않는다. 원본의 broad network 기본값 대신 전용 좁은 네트워크를 기본값으로 덮어쓴다.

Postfix master의 root 실행은 Trivy DS-0002 HIGH로 남아 있으며 권한 분리·chroot·최소cap·무공개 SMTP포트는 완화책이다. 오탐/수정으로 간주하지 않는다. 사용자 위험 수용 여부를 질문한 상태이며 승인 전 securityCheck/acceptanceTest와 운영 전환은 차단한다. 애플리케이션과 worker는 계속UID10001 비루트다.

SMTP 중계의 큐·테스트 수신함·계정 맵은 용량이 제한된 메모리 파일시스템만 사용하며, 인증번호와 수신 주소를 SMTP 영속 볼륨에 남기지 않는다. SMTP 큐는 최대5분이며 재시작 시 소실될 수 있다. 애플리케이션 PostgreSQL의 발송 대기 내용은 별도로 암호화해 재시도하지만, SMTP 수락 이후의 받은편지함 도착을 보장하지 않는다. 메일이 도착하지 않으면 새 인증번호를 요청해야 한다. 미래 결제 기능의 영수증 발송·재전송 보장은 그 기능을 구현할 때 별도 검증한다. 이메일 데이터 키를 분실하거나 기존 DB와 다른 키로 교체하면 복호화와 복구가 불가능하므로 기존 키를 별도로 안전하게 보관·이관한다.
