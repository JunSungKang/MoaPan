# 서버 메모리 캐시 검증서

> 문서번호: MP-DOC-031 · 기준: 저장소 현재 리비전 · 상태: 서비스 반영 검증 완료 · 작성: 개발 담당 · 검토: 독립 리뷰 담당

## 적용 결과
기존 브라우저 API 조회가 Caffeine 공통 메모리 캐시를 실제 사용한다. API를 새로 연결하는 사용자 작업은 없다. 브라우저 최적화 PR16과 기반 PR17에 이어 분류·대표 관심사·광고·지면·발간 도메인을 각각 전달한다. [통합 실행 증빙](evidence/cache-service-delivery-20261101.json)이 앞선 기반 전용 증빙을 보완한다.

| 도메인 | 실제 조회 경로 | 저장하는 공통 값 | 반복 조회 검증 |
|---|---|---|---|
| 분류 | 공개/회원 태그, 관리자 분류설정, worker 주제사전 | 정규화 태그·별칭·redirect·활성 주제 | 작은 저장 해시 1회, 사전 본문 SELECT 0회 |
| 대표 관심사 | 공개/회원 공통 대표 관심사 | 관리자가 정한 가중치·사용 가능한 태그·redirect | 저장 해시 1회, 설정 본문 SELECT 0회 |
| 광고 | 기존 회원 광고 표시 API | 승인된 공통 표시 설정 | 본문 매핑 재사용; 원래도 작은 행 1회이므로 왕복 감소를 주장하지 않음 |
| 지면 | 공개/회원 edition/page, 출처 목록 | 공통 후보 ID·요청 범위의 기사 카드·출처 | warm 기사/태그/번역/edition membership 본문 SELECT 각각 0회 |

공통 후보는 최근 공개 기사 최대300개의 계정 공통 후보이고 개인 관심사 목록이 아니다. 최초 공개 지면은 기존42건, 인증 페이지는 기존 요청 상한을 지키며 실제 요청 범위만 카드로 적재한다. 검색 결과·검색어·계정별 커서·권한·quota·세션·회원 관심사는 저장하지 않는다. 관리자 편집/초안 조회와 호출자 트랜잭션 내부 조회는 캐시를 우회한다.

## 갱신·동시성
수정 트랜잭션의 PostgreSQL 트리거가 출력에 영향을 주는 필드의 해시를 저장한다. 읽을 때 작은 해시와 현재 공개/권리 조건을 확인하고 달라지면60분 전이라도 즉시 재적재한다. 읽기 요청에서 원문 전체를 가져와 해시를 다시 계산하지 않는다. 변경 없는 같은 값은 최대60분 재사용한다. 지면 후보의 기존15분 선정 주기와 캐시 보관기한은 구분하며 후보와 내용이 같으면 새 edition ID 사이에서도 카드 객체를 재사용한다.

miss 적재는 동일 REPEATABLE_READ snapshot에서 해시와 값이 일치하도록 읽고 commit 뒤 공유한다. 동시 miss는 합치며 rollback·실패·과대 값은 공유하지 않는다. 중첩 목록/Map은 불변이다. 여러 인스턴스는 같은 DB 지문을 매 요청 읽어 변경을 감지한다. 인증·혜택·뉴스레터 근거의 현재 공개권한·quota·cursor 검사는 매 요청 수행한다. API Cache-Control은 no-store를 유지한다.

web16MiB/worker8MiB는 고정된 논리 가중치 예산이며 실제 JVM 전체 heap 상한이 아니다. 실제 한 번 관찰한 전체 컨테이너 메모리는 web475.3MiB/worker386.8MiB였다. 키·캐시 구조·객체 그래프·GC의 전체 retained size를 이 수치나 가중치로 보증하지 않는다.

## 검증과 실제 반영
통합330 PASS(단위164/PostgreSQL107/Playwright59), failure/error/skip0. Nu HTML 메시지0. strict verification·lock·licenseCheck·소스/JAR/SBOM·최종 앱/빌드/프록시 이미지 gate PASS. 원본 proxy 보고서의 GO-2026-5932 UNKNOWN은 이전 정확한 코드 부재 근거로 판단하며 탐지0으로 표시하지 않는다. 기존 S07 비밀번호 정책 차이는 사용자 유지 조건으로 미해결 상태다.

V17~22를 실제 PostgreSQL18.6에 적용했다. 암호화 백업을 격리 DB에 복원해300기사·비활성 계정·세션0을 확인하고 격리 DB를 제거했다. 원래300기사·2계정·1발간물의 ID 집합 해시가 반영 전후 일치했다. DB/모델 이미지와 볼륨은 유지했다.

실제 web/worker 이미지 sha256:6542dd108cb892fabd214a39b304680e5f5f1e7e0625ee499f6452286627646d의 JAR SHA-256은113f46dcf6054f4fc9d12b368ecbdfe23894750f5e8d1d7446b7d555062397a3이며 호스트 산출물과 같다. HTTPS에서 공개/보호 경계·일반회원 ADMIN403·태그/대표/기사/발간물 반복 조회·공유 자산304를 검사했다. 실제 web JVM에 캐시Entry9개와 카드/발간 상세 객체가 유지됐다. 합성 검증 계정은 삭제했다. 현재 실행의 별도 휴대폰 데이터망 재측정은 하지 않았으며 기존 승인된 IP의 HTTPS를 이 Mac에서 검증했다.

HTTPS 단일 cold/warm 관찰은 공개지면174.79→57.82ms, 발간상세57.93→12.69ms였다. 각1쌍 측정이라 통계적 성능 보장이나 개선율로 일반화하지 않는다. payload SQL 제거·불변 객체 재사용 시험이 기능 검증의 근거다.

## 발견·수정 이력
- 기반 DB 재시작 시험: Docker 임시 포트 변경으로 최초 연결 실패 → 새 매핑을 조회해 같은 보존 기준 재검증 PASS.
- 분류 job/article 트리거: 강제 latch 시험에서 실제 deadlock FAIL → article parent 잠금 없는 별도 분류상태 지문으로 수정 → 같은 시험과 전체 PG PASS.
- 실제 HTTP 시험: 수동 context.close의 종료 순서 오류 → Spring이 pool 뒤 DB를 닫도록 disposable dependency 정리 → 전체 suite 오류0.
- 전체 기사 입력/원문/회원 행위는 이 기능의 DB·메모리 공유 캐시에 추가 보관하지 않는다. 알려지지 않은 취약점이나 모든 공격 차단을 보증하지 않는다.
