## 회수 시각과 이용 종료 일치 검증 — 2026-11-02

권한 회수 시 서버가 계정 잠금과 version 확인 후 확정한 시각을 expires_at, updated_at, 회수 감사 created_at에 동일하게 저장한다. 시작 예정일은 변경하지 않는다. 이미 회수된 구독의 현재 version 요청은 종료·version·감사를 추가 변경하지 않고, 구 version은409를 유지한다. 재부여는 정상 기간 검사를 다시 거친다.

변경 전 PG3건이 종료일 잔존으로 실패했다. 수정 후 전체369건(단위171/PG128/브라우저70), 실패·오류·skip0을 통과했다. PG는 이용 중·시작 전·만료 후 회수, 동일 이벤트 시각, 중복 요청, 구 version, 재부여와404를 검증했다. 별도 PostgreSQL에서 V23 기존 자료를 만든 뒤 V24를 적용해 이전 회수 종료일 보정, 수정 행 version 증가, ACTIVE/이미 보정된 REVOKED 보존 및 반복 migration/validate를 확인했다. 브라우저는 회수 후 목록 종료일과 편집기의 한국시간 입력값 갱신을 확인했다. Nu12페이지 메시지0, source/JAR/SBOM/Helm 및 최종 runtime/builder image와 실제 truststore 검사를 통과했다.

최종 runtime `sha256:24fc8045a50cc78f44a57d0bdae30b12ed3d8bb52fcde7a1fa5e2042fafbf082`, builder `sha256:08e298f1a02b6790992334dcc4e9e863b11885d68f64bb120ba161dfa9dca7c1`, 호스트/web/worker JAR `8d471680b8a67ad6809d63479e96d80c5ec46087831cca6d6d4f80dc2c2cd36e` 일치. 기존 쓰기가 보정과 경합하지 않도록 web/worker를 잠시 중지한 뒤 V24 migration 성공과 재시작을 확인했다. 반영 직전 기사347/계정2/발간물1/구독1을 보존했다. 실제 기존 보정 대상은0건이며, 보정 후 구독 상태 해시는 사전 계산한 예상값과 일치한다. 현재 스키마는24다.
