# 문서관리계획서

문서번호: MP-MGT-001 · 상태: 적용 · 작성: 개발 담당 · 검토: 독립 리뷰 담당

## 관리 기준
- 단계별 산출물대장을 기준으로 생성·수정·폐기한다. 산출물에는 목적, 적용 범위, 구현 또는 증거 참조를 작성한다.
- 요구사항정의서 → 기능명세서 → 설계서/프로그램목록 → 시험케이스/결과의 REQ/FS/AC 추적을 유지한다. 기존 추적 ID를 변경하지 않는다.
- 기능 변경자는 분석·설계·시험 문서를 함께 갱신하고 독립 리뷰에서 정합성을 확인한다. 운영 변경은 이행·운영 문서를 갱신한다.
- Git PR은 변경 검토 기록, 병합 커밋은 기준선이다. 문서에 승인된 것처럼 임의 서명하거나 승인일을 만들어 넣지 않는다.
- 현재 상태는 진척현황 하나에서 안내하고 시험 수치는 시험결과서/증빙에 기록한다. 과거 실행은 현재 PASS로 합산하지 않는다.
- JSON 증빙/이미지는 당시 값을 유지한다. 원문·비밀값·회원정보·모델 가중치는 산출물에 넣지 않는다. 재생성 가능한 대형 결과는 build/reports에 둔다.
- 실행 설정은 config, 실행 도구는 scripts에 둔다. 과거 계약의 경로는 이관대장으로 추적하며 승인 계약을 소급 수정하지 않는다.

## 검토와 검사
변경 전 대장과 참조를 확인 → 관련 산출물 갱신 → docsCheck 및 영향 테스트 → 독립 리뷰 → PR 기준선 확정 순서다. docsCheck는 파일/링크/대장/도메인 경계의 구조를 검사하며 문서 내용의 정확성을 자동 보장하지 않는다. CI/CD 없이 Gradle check에서 실행한다.
