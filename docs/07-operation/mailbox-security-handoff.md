# 외부 MailBox 보안 결함 조치 요청서

> 문서번호: MP-DOC-039 · 상태: 전달용 프롬프트 작성, 타 프로젝트 미수정 · 작성: 개발 담당 · 검토: 독립 리뷰 담당

이 문서는 외부 MailBox 담당 작업에 복사할 프롬프트다. 작성·전달 준비는 MailBox 패치나 배포 완료를 뜻하지 않는다. 담고담고의 SMTP 클라이언트 책임과 외부 메일서버 책임을 구분한다.

```text
MailBox 프로젝트의 메일 인프라 보안 결함을 수정하라.

범위: MailBox 저장소·소유한 메일 컨테이너만 수정하고 담고담고(moapan)·전역 Codex 설정은 수정하지 않는다. 기존 메일·계정·큐·볼륨·사용자 변경을 보존하고 해당 저장소 AGENTS.md/작업·GitHub 절차를 따른다.

확인된 현상(2026-11-04 09:22 KST 검사 기준):
- SMTP 이미지 sha256:594e743418aadf1ed23478ba448bcb6cad5809c99858ecca9c06e43d7de12c99, Debian12.15/Postfix3.7.11-0+deb12u1. HIGH33/CRITICAL1은 패키지 중복을 포함한 원시 검출이며 실제 영향 판정과 구분한다.
- STARTTLS, 운영자 CA·호스트 검증, 합성 Maildir 수신은 성공했다. 이를 보존한다.
- root 실행, 사설망 전체 mynetworks, SMTP AUTH 미설정, 공개25번 및 smtp_tls_security_level=may를 검토한다. 외부 무인증 릴레이 가능성은 별도 시험 전 확정하지 않는다.

수정·검증:
1. 현재 실제 digest와 패키지를 재확인하고 공식 공급자 공지로 각 고위험 검출의 영향·수정 버전·실행 조건을 대조한다. Postfix CVE-2026-43964를 확인한다.
2. CVE-2023-45853은 MiniZip 관련이다. Debian의 해당 zlib에서 취약 MiniZip 바이너리를 빌드하지 않는다는 설명과 실제 설치 파일을 대조한다. 영향 없음은 정확한 패키지·조건·근거·재검토 기한으로 입증한다.
3. 영향 있는 취약점은 패치한다. 현재 배포판에 수정이 없으면 지원되는 기반으로 이관하되 데이터·기능을 검증한다.
4. root가 필요한 프로세스와 이유를 조사한다. root 위험 수용은 미승인이다. USER 문자열이나 sudo/setuid로 숨기지 말고 비루트 실행이 가능한 구성/대안을 실제로 검증한다.
5. 인터넷 수신과 앱 제출 경로를 구분한다. 사설망 전체 신뢰 대신 필요한 제출 주체만 허용하고 비신뢰 주체의 외부 중계 거부를 시험한다. 정상 수신을 임의 중단하지 않는다.
6. 인증·복구 메일 경로에서 TLS·인증서·호스트 검증을 유지하며 실패 시 평문 fallback 대신 실패/대기 처리한다.
7. 새 이미지 digest·OS/패키지·설정·비밀값 검사, CA/호스트 검증·중계 차단·합성 전달·재시작 데이터 보존을 확인한다.

금지: TrustAll/호스트 검증 해제/TLS 비활성화/전역 ignore/검사 제외로0건 만들기/검사 오류의 성공 처리. 비밀번호·인증번호·메일 본문·개인키를 출력하지 않는다. 승인되지 않은 외부 수신자에게 시험 메일을 보내지 않는다.

인도: 수정 전후 digest·발견별 근거·실제 시험·남은 차단사항. 담고담고가 사용할 SMTP 호스트/포트/TLS/네트워크·CA 공개 인증서와 인증정보의 안전한 설정 방법을 제공한다. private key와 비밀번호는 대화/보고서에 포함하지 않는다.
```

공식 확인 출처: [Debian Postfix](https://security-tracker.debian.org/tracker/CVE-2026-43964), [Debian MiniZip/zlib 범위](https://security-tracker.debian.org/tracker/CVE-2023-45853). 원시 보고서는 이전 MP-DOC-038 제11~12절의 검사 시각에 해당한다. 이후 새 이미지는 별도로 검사한다.

개별 패키지·설치 버전·원시 CVE 목록은 [전달용 검사 증빙](../05-test/evidence/mailbox-image-findings-20261104.json)에 있다. 이 증빙은 MailBox를 이번 작업에서 다시 실행/검사/수정한 결과가 아니며 앞서 수행한 검사를 전달용으로 정리한 것이다.
